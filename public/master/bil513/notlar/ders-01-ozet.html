Answer pattern#

  • Explain using state, mode or CPU ownership sl. 26. Name the axis you are using.
  • Separate two questions: did privilege change? did the task change? sl. 24 · eligibility to run vs current CPU ownership sl. 19.
  • Predict, then state the assumptions that make the answer valid ("assuming no explicit shared memory") sl. 60.
  • Say "not necessarily" when the interface promises no order. A trace is "a possible execution order, not a measured trace" sl. 19.

The seven contrasts sl. 64#

  1. Program vs process: a program is a passive description in a file; a process is a running instance with its own PID, PC, registers, address space and kernel-recorded resources.
  2. Process vs thread: a process is a resource and protection context; a thread is a flow of execution inside it with its own PC, registers and stack, sharing the address space and open files.
  3. Ready vs running vs waiting: ready = able to run, needs a CPU (policy matters); running = on a CPU; waiting = an event is missing, more CPU does not help.
  4. Kernel entry vs task switch: entering the kernel (system call, exception, interrupt) changes privilege; a task switch changes which task owns the CPU. Either can happen without the other being implied.
  5. fork vs exec vs wait: fork creates a child with a copied view (new PID); exec replaces the program image (same PID, does not return on success); wait observes termination and collects status (no new process).
  6. Concurrency vs parallelism: concurrency = overlapping lifetimes, possible on one core; parallelism = simultaneous execution on different cores.
  7. Shared memory vs pipe: shared memory = a common region, needs explicit synchronization; a pipe = a kernel byte stream with blocking and EOF rules, no message boundaries.

Mechanisms in one line each#

  • Three reasons to enter the kernel sl. 8: system call (requested), exception (caused by the current instruction, e.g. page fault), device interrupt (independent event, e.g. timer, I/O completion).
  • Timer = an opportunity for the kernel to decide, not a command to switch. Control must not depend on voluntary cooperation.
  • Context switch sl. 22–23: save P's context, select a runnable task, restore Q's context. Not copying all memory. Cost = direct save/restore + indirect working-set effects (caches, translations). Policy balances responsiveness and fairness against switching cost.
  • PCB sl. 14–15: identity, state, saved context, references to memory mappings and open files. "A process record is not a memory snapshot."
  • CPU-bound = mostly ready or running; I/O-bound = frequently waiting. Not permanent labels sl. 21.
  • Zombie = terminated, status not collected, not executing. Orphan = parent exited, may still run, is reparented sl. 39.
  • Pipe lifecycle sl. 62: close unused ends in every process, readers must see EOF, child statuses must be collected.
