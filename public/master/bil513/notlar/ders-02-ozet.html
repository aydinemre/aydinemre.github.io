Answer pattern#

  • State the model before the number: one CPU or several, arrivals, known or estimated bursts, switch cost, tie rule, priority direction sl. 18, 37; Okuma §7.
  • Construct a legal schedule first, then extract S and C, then compute metrics. Never read waiting off a bar's position when a job has several bars Okuma §7.
  • Name the criterion ("best according to which criterion?"): mean waiting, response, fairness or deadlines are different objectives sl. 16, 34, 66.
  • Separate a sufficient test from a necessary condition and a trace from a guarantee: "A finite trace illustrates decisions. The feasibility theorem provides the guarantee" sl. 52, 57.
  • Ready vs blocked: priority or more CPU cannot supply a missing part or a held lock sl. 8, 58.
  • Observation answers: record the environment, say what the evidence cannot prove sl. 62–63.

Formulas and calculation steps#

1. Per-job accounting sl. 16–17; Okuma §4. A = arrival, S = first start, C = completion, B = total CPU demand.

  • T = C − A; R = S − A (first CPU service, not first visible output); W = time ready but not running.
  • CPU-only job: W = T − B. Slide check: A 2, S 5, C 12, B 4 → T 10, W 6, R 3 sl. 17.
  • Utilization = busy time / elapsed time; throughput = completed jobs / time sl. 16.

2. With I/O sl. 17; Okuma §4: W = T − (CPU time) − (blocked time). Blocked time is device waiting, never ready-queue waiting. Safer: add up the intervals in which the job was ready but not running.

3. Exponential averaging sl. 25–26; Okuma §6: τ(next) = α × t(actual) + (1 − α) × τ(previous). α = 0.5, τ = 10, t = 6 → 8; then t = 4 → 6. α = 0: never updates; α = 1: last burst only. Large α reacts fast but follows noise; small α smooths but adapts slowly.

4. Round robin gap sl. 30; Okuma §8: gap between a task's turns ≤ (n − 1)q, only if n continuously runnable equal peers, zero overhead, no outside arrivals. Overhead, higher-priority work or a changing ready set breaks it.

5. Quantum cost sl. 32; Okuma §8: useful fraction ≈ q/(q + s) for saturated alternating work. q = 4 ms, s = 0.2 ms → 95.24%; q = 1 ms → 83.33%. Turnaround vs q is not monotonic; huge q → FCFS sl. 33.

6. Liu–Layland (RM, sufficient) sl. 52; Okuma §12: U = Σ Ci/Ti ≤ n(2^(1/n) − 1) ⇒ schedulable. Values: n = 1: 1.0 · n = 2: 0.8284 · n = 3: 0.7798 · n = 4: 0.7568 · n = 5: 0.7435 ek bilgi: values for n = 1, 3, 4, 5 computed from the formula. Above the bound → inconclusive, go to RTA.

7. RTA iteration (RM, D = T) sl. 54; Okuma §12: R0 = Ci; R(next) = Ci + Σ over higher-priority j of ceil(R/Tj) × Cj. Iterate until R repeats (meets if R ≤ Di) or exceeds Di (miss). R = release-to-completion, not first service. Example B, P2: 35 → 60 → 85 > 80. Assumes independent, preemptible tasks, no blocking or overhead.

8. EDF sl. 55–56; Okuma §13: run the ready job with the earliest absolute deadline d = r + D. One processor, independent, fully preemptible, D = T: U ≤ 1 is exact. If D < T, or with blocking, overhead, jitter or several CPUs, utilization alone is insufficient sl. 56.

9. Little's law sl. 65; Okuma §15: Lq = λ × Wq (stable queue, matching boundaries). λ = 7 jobs/s, Lq = 14 → Wq = 2 s. If the count includes running work, use time in system. Overloaded, growing queue: no steady state, no answer.

10. Gantt checklist sl. 18, 27, 35, 67; Okuma §7, §15

  1. Write the rules: [start, end) intervals, tie order, SRTF tie → current job continues sl. 27, RR order of a new arrival vs an expired quantum Okuma §8, priority direction (textbook: smaller = higher; Linux RT: opposite) sl. 37.
  2. Mark every arrival, preemption and completion; at each event compare remaining demand (SRTF) or absolute deadlines (EDF), not original bursts or periods sl. 27, 57.
  3. Nonpreemptive policies only decide when the CPU is free; a job that finishes at t frees the CPU at t sl. 18.
  4. Conservation check: each job's executed time = its demand; nothing runs before release; no overlap on one CPU; last completion = total work + idle time Okuma §7, §15.
  5. Then compute S, C → T, W, R per job, then the means; report the distribution too, not only the mean sl. 64.
  6. Real-time: check up to the hyperperiod lcm(Ti); demand in it = U × hyperperiod ek bilgi: hyperperiod as the check horizon.
